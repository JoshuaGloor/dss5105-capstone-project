# Generated chat train/test evaluation sets and results

## Evaluation sets

Supplementary generated cases are in `examples/eval_sets/`:

| Split | IDs | Cases | Construction |
|---|---:|---:|---|
| Training supplement | TR071-TR140 | 70 | 10 each across the seven course request kinds |
| Test supplement | TE071-TE100 | 30 | Course inbox mix: 7 meetable, 3 impossible, 6 constraint, 4 ambiguous, 3 missing-field, 4 ineligible-suggestion, 3 unanswerable |

The requests and rubrics are generated by `scripts/extend_eval_sets.py` with
separate seeds and split-specific wording. Fields are labels by construction;
expected states for complete and constraint cases use the deterministic dispatch
preview. These are not human gold annotations. Test wording is distinct from
training wording, but the test set is a true holdout only if it is kept out of
prompt and tool tuning. The original 70-case training and 35-case test sources
are retained in the archived run's manifest/source snapshot.

## Supplied run results

The supplied `results.zip` contains completed `train-1` and `test-1` runs using
the original 70/35-case split. It does not contain runs for the supplementary
TR071-TR140 and TE071-TE100 cases. Raw per-case JSON, summary, manifest, and source
snapshot are preserved under the ignored `results/train-1/` and `results/test-1/`
directories, following the runner's results layout.

| Check | Train (n=70) | Test (n=35) |
|---|---:|---:|
| Completed responses | 70/70 | 35/35 |
| Required extraction checks | 70/70 | 34/35 |
| Draft behavior rubric | 67/70 | 34/35 |
| Tool integrity | 70/70 | 35/35 |
| Display fields checked | 1,720 | 848 |
| Provider-reported tokens | 76,249 | 38,050 |

The test draft-rubric result is 34/35 (97.1%); the training result is 67/70
(95.7%). These are generated-rubric pass rates, not overall accuracy. The test
failure is TE035, a question about unavailable margin data that was not handled
according to the draft rubric. Training failures are TR053, TR056, and TR059;
each is an ineligible-workshop suggestion where the model's unnecessary quantity
question blocked the expected refusal. Raw inputs, model outputs, and tool traces
are in the corresponding case JSON files.

## Interpretation and limits

The supplied run used `openai:gpt-5.6`, `intake-v2`, no automatic retries, and a
30-second timeout. Each request used the same independent 2026-04-01 queue
snapshot. It measured a single initial response, not a multi-turn clarification
conversation. Tool integrity is a partial field-level check, not full explanation
faithfulness or UI evaluation. Generated labels and the draft rubric can miss
semantic errors; the pass counts must not be called model accuracy.

The archived test results are usable as the supplied comparison run, but the
archive does not prove whether those cases influenced development or tuning. The
new supplementary test split should be run only after its rubric and prompt/tool
configuration are frozen if it is to support a held-out claim. That live run
requires the configured provider credentials. No provider call was made while
processing the supplied archive.

To run the new generated splits, use a fresh output directory for each run:

```bash
uv run --locked python -m dss5105.evaluate_chat --set train_extra --live --output results/train-extra-1
uv run --locked python -m dss5105.evaluate_chat --set test_extra --live --output results/test-extra-1
```

These are paid provider runs. Do not run them until the team intends to spend
provider tokens and the test split is frozen against tuning.
